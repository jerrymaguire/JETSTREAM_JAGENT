# 测试与验收设计

## 1. 验收目标

最终实现必须用可重复的测试和截图证明：

- 作业五 P0 要求全部满足。
- 示例会话的总时长、轮次和调用信息正确。
- 多轮次、失败调用和父子关系可辨认。
- 通用导入路径可用。
- 桌面和移动端均可完成核心操作。

## 2. 测试分层

### 2.1 单元测试

| 对象 | 用例 |
|---|---|
| adapter 检测 | 标准格式、未知格式、空输入、错误 JSON |
| adapter 转换 | 时间、类型、状态、父调用、摘要生成 |
| validator | 字段缺失、时间逆转、环关系、轮次缺口 |
| analytics | 总时长、轮次、错误率、活跃时长、token |
| query | 关键词、类型、状态、轮次组合筛选 |
| time layout | 起点、宽度、最小点击宽度、可见域 |
| redaction | API Key、Token、路径和敏感字段 |

### 2.2 组件测试

- KPI 带显示正确值。
- 选中行后详情联动。
- 搜索后列表和命中数同步。
- 轮次切换后分组正确。
- 错误调用显示红色状态和错误摘要。
- 键盘 J/K 改变选中项。
- 空、加载、错误状态渲染。

### 2.3 端到端测试

| 场景 | 步骤 | 验收 |
|---|---|---|
| E2E-01 打开示例 | 首页点击加载示例 | 出现 3.40s、1 轮、2 次调用 |
| E2E-02 选择调用 | 点击第 2 条调用 | 详情显示正确名称和时间 |
| E2E-03 搜索 | 输入 `FAQ` | 只保留命中调用并高亮 |
| E2E-04 轮次筛选 | 选择轮次 1 | 列表和 KPI 范围同步 |
| E2E-05 导入标准文件 | 导入 `agent-show/v1` | 进入新会话工作台 |
| E2E-06 导入未知格式 | 导入通用 JSON | 显示字段映射 |
| E2E-07 错误数据 | 导入时间逆转数据 | 显示阻断错误，不写入 |
| E2E-08 删除会话 | 删除本地会话 | 列表移除并显示恢复空状态 |
| E2E-09 手机布局 | 375px 打开示例 | 可选择调用并打开底部详情 |
| E2E-10 深色主题 | 切换主题 | 对比度和选中态保持可辨 |

### 2.4 视觉回归

截图视口：

- 1440 x 900，浅色。
- 1440 x 900，深色。
- 1024 x 768。
- 390 x 844。

检查：

- 文本不重叠。
- 时间轴与 KPI 对齐。
- 右栏不遮挡中央内容。
- 长标题不撑破顶栏。
- 表格和条形没有布局跳动。

## 3. 示例数据验收值

示例会话建议包含：

- 1 个完整会话。
- 3 个轮次。
- 17 次调用。
- 至少 1 次工具调用、1 次 LLM 调用和 1 次失败调用。
- 至少 1 组父子调用。
- 可计算总时长。
- 可计算 token 总量。

参考截图可提供一个基础场景，但正式示例数据需要扩展为多轮次和多状态，以覆盖加分项。

## 5. 质量门禁

### 5.1 硬门禁

- 设计符合性 100%。
- TypeScript 编译无错误。
- 0 个 Blocker 或 Critical 质量问题。
- 0 个高危安全或隐私问题。
- 所有 P0 需求有测试或人工验收证据。

### 5.2 软门禁

- 行覆盖率不低于 80%。
- 分支覆盖率不低于 70%。
- 需求到测试覆盖率不低于 90%。
- Lighthouse 性能不低于 85。
- 所有自动化可访问性检查无严重问题。

## 6. 性能测试

测试数据：

- 500 次调用。
- 5,000 次调用。

指标：

- 首次可交互小于 2.5 秒。
- 滚动时不出现长任务超过 200ms。
- 筛选结果反馈在 100ms 内开始。
- 详情切换不触发整页重新布局。

## 7. 隐私验收

- 示例 JSON 扫描无 `api_key`、`token`、`secret`、`password`、Bearer Token。
- 截图不显示用户主目录和个人标识。
- 浏览器网络面板确认无数据上传请求。
- 清空本地数据后 IndexedDB 无残留会话。

## 8. 人工演示脚本

1. 打开首页，点击“加载示例”。
2. 指出总时长、轮次、调用数。
3. 点击一条工具调用，展示开始时间和持续时长。
4. 切换到轮次视图，定位到第 2 轮。
5. 搜索一个工具名，展示命中高亮。
6. 打开一次失败调用，展示错误信息和原始数据。
7. 切换深色主题。
8. 调整到手机宽度，展示底部详情抽屉。
