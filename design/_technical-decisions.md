# 技术决策

## TD-001 应用形态

- 决策：单体、纯前端、本地优先单页应用。
- 理由：作业范围集中，本地文件即可完成展示，部署和验收成本最低。
- 代价：不提供跨设备同步和实时采集。
- 重评条件：出现团队协作、服务端采集或大规模集中存储需求。

## TD-002 前端框架

- 决策：Vue 3 + TypeScript + Vite。
- 理由：与 `software-delivery` 默认前端交付基线一致，组件生态成熟，构建简单。
- 约束：组合式 API，业务状态放 Pinia，纯展示状态保留在组件内。

## TD-003 UI 基础

- 决策：Element Plus 只承担基础控件，轨迹可视化使用自定义图层。
- 理由：Element Plus 适合按钮、弹窗、标签、输入和抽屉，不负责高密度时间轴。
- 约束：统一覆盖设计 token，禁止使用未经调整的默认组件视觉。

## TD-004 统一轨迹模型

- 决策：所有输入归一化为 `TraceSession v1`。
- 理由：可视化、指标和详情面板只依赖一个稳定模型。
- 约束：原始数据保留在 `raw` 命名空间，不得反向污染统一字段。

## TD-005 Adapter 机制

- 决策：使用注册式 adapter，接口包含 `detect`、`normalize`、`validate`。
- 首批 adapter：
  - `agent-show/v1`
  - `generic-json-map`
  - `otel-genai` 设计预留
- 理由：先保证通用扩展边界，再逐步增加具体格式。

## TD-006 本地持久化

- 决策：Dexie + IndexedDB。
- 理由：会话和原始 JSON 可能超过 localStorage 容量，IndexedDB 更适合大对象。
- 约束：用户可删除单条会话和全部本地数据。

## TD-007 数据校验

- 决策：导入后先校验再入库。
- 必校验：
  - 会话和调用 ID 唯一。
  - 时间可解析。
  - `endedAt >= startedAt`。
  - `roundId` 和 `parentId` 可解析。
  - 批次与轮次数量一致。
- 策略：阻断型错误阻止导入，非阻断型问题形成 warning 并显示在导入摘要。

## TD-008 时间标准

- 决策：存储 ISO 8601 UTC 时间，展示使用浏览器本地时区。
- 理由：避免夏令时和时区切换导致错位。
- 约束：`durationMs` 优先由起止时间计算；缺失时才使用显式 duration。

## TD-009 可视化实现

- 决策：D3 时间比例尺 + 自定义 SVG/DOM 行布局。
- 理由：需要调用重叠、层级、选中、缩放、虚拟化和可访问语义，通用图表库难以同时满足。
- 约束：视觉层不把每个像素绘制到 Canvas 作为主实现，详情行保持 DOM 可访问。

## TD-010 大数据虚拟化

- 决策：瀑布行使用 TanStack Vue Virtual。
- 理由：5,000 次调用时避免每次筛选重建全部 DOM。
- 约束：总览轨道可以按时间分桶聚合，避免绘制不可辨认的密集条形。

## TD-011 状态管理

- 决策：Pinia 管理会话、选中调用、筛选和持久化偏好。
- 理由：三栏联动和 URL 状态需要单一事实源。
- 约束：连续缩放和拖动优先使用局部值或 requestAnimationFrame 节流，不把每一帧写入全局 store。

## TD-012 主题与视觉

- 决策：CSS 变量定义语义 token，支持浅色、深色和跟随系统。
- 视觉方向：中性底色、蓝色单一交互强调、状态色只用于语义。
- 约束：不使用紫色渐变、玻璃拟态、装饰性光晕和过多卡片容器。

## TD-013 隐私安全

- 决策：默认完全本地运行。
- 措施：
  - 不进行网络上传和遥测。
  - 导入前提示可能包含敏感信息。
  - 提供一键脱敏预览。
  - 示例数据人工脱敏。
  - 截图和录屏不展示凭据。

## TD-014 测试

- 决策：Vitest + Vue Testing Library + Playwright。
- 覆盖：
  - adapter 和派生指标单元测试。
  - 选择、筛选、详情联动组件测试。
  - 导入、打开示例、轮次定位、错误详情 E2E。
  - 桌面和移动截图回归。

## TD-015 构建与交付

- 决策：Vite 静态构建，可选 Vercel、Netlify 或本地静态服务器。
- 默认交付目录：`deliverables/frontend/`。
- 首版不引入后端、数据库和 Docker 运行依赖。
