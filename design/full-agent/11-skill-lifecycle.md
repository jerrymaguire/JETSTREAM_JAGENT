# Skill 生命周期设计

## 1. 定位

Skill 保存可复用的方法、输入要求、配套材料和验收标准。它不是工具权限，也不是 Agent。

当前不实现 Subagent。主 Agent 可以直接自动选择 Skill、由用户显式调用，或通过 Skill 目录查看可用能力。

## 2. Skill 与相邻概念

| 对象 | 职责 |
|---|---|
| Tool | 执行具体动作 |
| Prompt | 表达本次或通用指令 |
| Skill | 保存稳定方法、材料入口和验收方式 |
| Agent | 根据观察选择动作并执行 |
| Context | 本次真正提供给模型的内容 |

Skill 被加载不代表工具被授权，也不代表任务完成。

## 3. 目录

```text
skill-name/
├─ SKILL.md
├─ references/
├─ scripts/
└─ assets/
```

## 4. 元数据

```yaml
---
name: codebase-review
description: 审查仓库的架构、测试、安全和性能。适用于代码审查任务。
metadata:
  version: "1.2.0"
  owner: platform-team
  maintainers:
    - engineer-a
  reviewed_at: "2026-11-19"
  compatibility: "AgentShow >= 1.0"
---
```

版本只有被加载记录、请求记录和评测记录实际使用，才算真正可追踪。

## 5. 稳定方法与现场信息

Skill 中应写：

- 适用范围。
- 输入要求。
- 检查步骤。
- 证据要求。
- 验收方式。
- 权限和失败边界。

Skill 中不应固化：

- 当前项目路径。
- 当前 API Key。
- 旧版本业务规则。
- 仅对某一次任务有效的文件位置。
- 过度具体的模型或工具参数。

当前规则由 Task 或用户输入提供。

## 6. 加载方式

### 自动选择

1. Pi 启动时发现 Skill。
2. 系统提示中加入名称、description、路径和版本。
3. 模型判断匹配。
4. 模型通过读取工具读取 `SKILL.md`。
5. 需要时继续读取 references 或执行 scripts。

### 显式调用

1. 用户输入 `/skill:name`。
2. Pi 读取 Skill 正文。
3. 正文和用户参数进入当前输入。
4. 实际工具调用仍受治理。

显式调用不一定产生读取 `SKILL.md` 的工具记录，因为宿主可能直接展开正文。验证时必须检查实际模型请求。

## 7. 渐进式披露

必须区分三个环节：

1. 程序读取文件并解析元数据。
2. 能力目录进入系统提示。
3. 正文或引用材料进入实际请求。

只有第 3 步能证明模型看过完整 Skill。

## 8. 预算

记录：

- Skill 目录字符数。
- 实际加载正文的字符数和 token。
- 配套参考资料。
- 脚本输出。
- Skill 带来的总调用成本。

渐进加载减少无关内容，但正文和工具结果仍消耗预算。

## 9. 脚本与权限

三层限制：

| 层 | 责任 |
|---|---|
| Skill | 说明脚本用途、输入、输出和失败处理 |
| Tool Governance | 决定能否执行、是否需要审批 |
| Sandbox | 限制文件、网络、进程和资源 |

Skill 正文写“允许执行”不会增加权限。

## 10. 验证

### 正例

相关任务应选择正确 Skill，并按步骤产出证据。

### 反例

不相关任务不应触发 Skill。

### 缺输入

缺少当前规则时，应查找权威来源；仍缺失则标记 unknown。

### 执行失败

脚本或依赖失败时，应如实报告，不伪造通过。

### 显式加载

检查正文是否进入实际请求。

### 自动选择

使用干净会话验证，不让旧会话历史干扰判断。

## 11. 版本与变更

每次 Skill 变更保存：

- skill id。
- version。
- content hash。
- source path。
- owner。
- changed files。
- reviewed_at。
- enabled。

运行和评测记录保存实际生效版本，而不是只记录当前磁盘版本。

## 12. 效果比较

固定：

- Task。
- 模型。
- Prompt。
- 工具和权限。
- 预算。
- 环境快照。
- Grader。

比较：

- 有效发现数。
- 遗漏数。
- 误报数。
- 是否编造证据。
- 耗时。
- Token 和成本。

报告更长不代表 Skill 更好。

## 13. Skills-as-Code

P2 支持：

- Skill 变更进入版本控制。
- 变更说明。
- CI 校验 frontmatter 和路径。
- 样例任务回归。
- 实际生效版本记录。
- 旧版本回滚。

## 14. 前端

Skill 页面展示：

- 名称、描述、版本、owner。
- 来源和作用域。
- 是否启用和是否可信。
- 自动选择状态。
- 脚本和 references。
- 最近验证结果。
- 实际加载记录。

当前不展示 Subagent 绑定。
