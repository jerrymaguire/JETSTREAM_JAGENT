# 产品设计

## 1. 用户目标

用户希望在一个本地工作台中完成：

1. 选择工作区和模型。
2. 与 Agent 连续对话。
3. 查看模型、工具和 Skill 的实时执行过程。
4. 管理模型 Provider 和 API Key。
5. 审批危险操作。
6. 查看一次会话的完整轨迹。
7. 继续、分支、导入和导出历史会话。
8. 在同一会话中指定目标，让 Agent 自动迭代直到完成。

## 2. 页面结构

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ AgentShow | 工作区 | 模型 | 运行状态 | 设置                              │
├───────────────┬─────────────────────────────────────────┬────────────────┤
│ 工作区         │ 对话 / 轨迹 / 产物                       │ 检查器         │
│ 会话列表       │                                         │ 工具调用详情   │
│ 新建会话       │ 消息流或轨迹画布                         │ Context/Usage  │
│ 搜索           │                                         │ 审批/原始事件   │
├───────────────┴─────────────────────────────────────────┴────────────────┤
│ Composer：附件 | Skill | 工具策略 | 计划/执行 | 发送                      │
└──────────────────────────────────────────────────────────────────────────┘
```

## 3. 核心用户流程

### 3.1 首次配置

1. 打开设置。
2. 新建 Provider。
3. 填 Base URL、协议和 API Key。
4. 保存加密密钥。
5. 测试连接。
6. 选择默认模型。

### 3.2 开始对话

1. 选择工作区。
2. 选择模型和思考等级。
3. 发送用户消息。
4. FastAPI 启动或复用 Pi Sidecar。
5. Pi 通过 FastAPI LLM Gateway 请求模型。
6. 事件实时推送到前端。
7. 工具调用进入授权和审批。
8. 最终回答写入消息流和轨迹。

### 3.3 目标模式

1. 用户在已有对话中点击“设定目标”。
2. 填写目标、完成标准、约束和预算。
3. FastAPI 创建 Goal。
4. Goal Supervisor 生成第一轮计划。
5. 系统在同一会话中启动一次 Pi Run。
6. Pi 执行模型和工具 Inner Loop。
7. 本轮结束后，系统收集输出和工具证据。
8. 验收器判断目标是否完成。
9. 未完成则总结进展并启动下一轮。
10. 完成、阻塞、取消或预算耗尽时停止。

### 3.4 查看轨迹

1. 切换到轨迹 Tab。
2. 查看总时长、轮次、调用数、token 和成本。
3. 在时间轴和瀑布图中定位调用。
4. 打开详情，查看摘要、参数、输出和错误。
5. 按轮次、类型和状态筛选。

### 3.5 审批工具

1. Agent 发起写文件或执行命令。
2. 系统创建审批单。
3. 前端弹出审批面板。
4. 用户批准或拒绝。
5. 批准后调用继续；拒绝后结果回灌模型。
6. 全程进入 Trace。

## 4. 核心对象

### Workspace

- 本地目录。
- 名称、允许路径、禁止路径、信任状态。
- 项目 Skills 和项目级记忆归属。

### AgentProfile

- Agent 名称。
- 系统提示词。
- 默认模型。
- 可用工具。
- Skill 目录。
- 运行预算。

### Session

- 一次长期对话。
- 关联工作区、AgentProfile 和 Pi session 文件。
- 可继续、分支、克隆和导出。
- 可包含多次普通消息交流。
- 同一时间最多有一个 active Goal。

### Run

- 一次用户输入触发的 Agent 执行。
- 包含多个模型和工具调用。
- 有状态、预算和结束原因。

### Goal

- 用户指定的目标。
- 包含完成标准、约束、预算和自动继续策略。
- 由外层 Goal Loop 驱动多次 Run。
- 有独立的进度、证据、迭代记录和结束原因。

### GoalIteration

- Goal Loop 的一轮。
- 记录本轮目标、计划、关联 Run、结果摘要、证据和判定。
- 每轮都可以继续、重规划、等待用户或结束目标。

### Trace

- 对 Run 的结构化观测。
- 作业五的主要展示对象。

### Provider 与 Model

- Provider 是上游服务连接。
- Model 是用户可选择的模型配置。
- Credential 是加密保存的访问密钥。

## 6. 产品边界

- 第一版为单用户本地工作台。
- 支持多个工作区，但一个会话绑定一个工作区。
- 支持多个 Provider，但每个请求只使用一个模型。
- 支持自动 Skill 选择和显式 Skill 调用。
- 长期记忆默认关闭或需显式开启。
- 允许导入外部 Trace，但不把外部 Trace 当作可继续的 Pi Session。
- 普通聊天与目标模式共用同一会话历史。
- 目标模式由 FastAPI 外层编排，不替代 Pi 在一次 Run 内的 Inner Loop。
