# 完全体 Agent 需求基线

## 1. 项目定位

AgentShow 是一个本地优先、可对话、可执行工具、可加载 Skill、可持续记忆并可视化完整轨迹的通用 Agent 工作台，体验目标接近 DeepSeek Harness。

系统由三个运行部分组成：

1. Vue 前端工作台。
2. FastAPI 控制平面和统一 LLM 网关。
3. Pi Agent Sidecar，使用 `@earendil-works/pi-coding-agent` 运行真实 Agent Loop。

作业五要求的“Agent 对话轨迹图”不再作为独立纯前端工具，而是完整 Agent 的运行观测视图。

### 3.1.1 目标驱动循环

一个对话允许包含多次普通交流，也允许用户为当前对话指定一个目标。目标由外层 Goal Loop 持续推进，直到验收完成或触发停止条件。

| 编号 | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| G-01 | 新建对话 | 对话框可创建全新会话，旧会话保留 | P0 |
| G-02 | 多轮交流 | 同一会话可持续发送多条消息并恢复上下文 | P0 |
| G-03 | 指定目标 | 用户可输入目标、完成标准和约束 | P0 |

## 5. 关键控制规则

| 规则 | 行为 |
|---|---|
| RULE-001 | API Key 保存后不可再次明文读取 |
| RULE-002 | Pi Sidecar 不持有上游 Provider 密钥 |
| RULE-003 | plan 模式禁止写文件和执行写命令 |
| RULE-004 | 高风险工具需要用户批准 |
| RULE-005 | 所有工具参数必须校验后才能执行 |
| RULE-006 | 命令环境变量中的 KEY、TOKEN、SECRET、PASSWORD 必须移除 |
| RULE-007 | 项目 Skill 未受信任时不得加载 |
| RULE-008 | 长期记忆写入必须保留来源 |
| RULE-009 | 中止 Run 必须同时取消 Pi 和正在执行的工具 |
| RULE-010 | Trace 和日志不得保存完整 API Key 或 Authorization Header |
| RULE-011 | 相同工具和参数重复调用超过配置阈值必须拦截 |
| RULE-012 | 工具结果进入上下文和进入审计数据库的截断策略必须分别可配置 |
| RULE-013 | 同一对话同时最多有一个 active Goal |
| RULE-014 | Goal Loop 必须每轮持久化进度和证据 |
| RULE-015 | Agent 不得仅凭自然语言自述把目标标记为完成 |
| RULE-016 | 目标完成必须由验收规则、确定性检查或用户确认放行 |
| RULE-017 | 连续多轮没有进展时必须停止并请求用户介入 |
| RULE-018 | Goal Loop 必须受总预算和单轮预算双重限制 |
| RULE-019 | 人工审批未完成时 Goal 必须进入等待状态 |
| RULE-020 | 用户取消目标后不得继续自动启动新的 Agent Run |
| RULE-021 | 每轮模型调用必须保存实际请求快照 |
| RULE-022 | execution_status、outcome_status 和 gate_status 必须分开 |
| RULE-023 | 被评 Agent 不得修改评测脚本、参考答案和门槛 |
| RULE-024 | 程序可验证事实优先使用 Program Grader |
| RULE-025 | 证据不足必须记录为 unknown，不得当作用通过 |
| RULE-026 | 运行和评测记录必须保存实际生效的 Skill 版本 |
| RULE-027 | 当前版本不得引入 Multi-Agent 或 Subagent |
| RULE-028 | 取消必须传播到 Pi、模型流、工具和子进程 |

## 6. 非目标

- 第一版不做公网多租户 SaaS。
- 第一版不实现移动端原生 App。
- 第一版不重写 Pi 的 Agent Loop。
- 第一版不保证兼容所有厂商协议，优先 OpenAI-compatible。
- 第一版不提供无人审批的 unrestricted shell。
- 当前不实现 Multi-Agent、Subagent 和角色编排。
- 当前评测范围为单个 Agent 配置，不评测 Agent 间协作。
